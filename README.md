# MLOps Weekly Assignment - Week 11

## Overview

This repository contains the implementation of the Week 11 MLOps assignment focused on **LLM Guardrails, Red-Team Evaluation, Prompt Injection, Prompt Leakage, and Guarded Model Evaluation**.

The pipeline evaluates two fine-tuned IRIS species classification model versions deployed on Vertex AI. The assignment performs adversarial testing against prompt injection and context leakage attacks, implements input and output guardrails, logs blocked and filtered requests for auditing, and measures the effectiveness of the guardrails on both adversarial and legitimate IRIS inputs.

The guarded pipeline follows the sequence:

```text
Input
  │
  ▼
Input Guardrail
  │
  ├── Blocked ──► Return blocked response
  │
  ▼
Vertex AI Model
  │
  ▼
Output Guardrail
  │
  ├── Unsafe ──► Return fallback response
  │
  ▼
Safe Species Classification
```

Two model versions are evaluated:

* v1
* v2

## Files

### app/input_guardrails.py

* Implements the input validation layer.
* Detects known prompt injection patterns.
* Uses rule-based keyword and regular-expression checks.
* Performs structural validation of IRIS feature inputs.
* Validates the required feature fields:

  * `sepal_length`
  * `sepal_width`
  * `petal_length`
  * `petal_width`
* Ensures feature values are numeric.
* Blocks suspicious requests before they reach the Vertex AI model.
* Logs blocked requests with timestamps and matching rules.

### app/output_guardrails.py

* Implements the output filtering layer.
* Scans generated model responses for context leakage.
* Detects system prompt and task configuration leakage.
* Validates the expected species output format.
* Allows valid IRIS species classifications.
* Converts valid natural-language classifications into the expected species format.
* Replaces unsafe or invalid responses with a standardized fallback message.
* Logs filtered responses for auditing.

### app/guarded_prediction.py

* Provides the complete guarded prediction pipeline.
* Receives the raw input.
* Applies the input guardrail.
* Calls the appropriate Vertex AI model when the input is valid.
* Applies the output guardrail to the model response.
* Returns either a blocked response, filtered response, or valid species classification.

### scripts/test_task_1.py

* Performs red-team evaluation for prompt injection.
* Tests adversarial prompts against both v1 and v2.
* Includes multiple attack patterns:

  * Instruction override
  * Role-play framing
  * Delimiter escape
  * Instruction injection inside feature values
* Records the raw model responses.
* Determines whether each attack successfully deviates from the expected species classification format.

### scripts/test_task_2.py

* Performs red-team evaluation for prompt leakage.
* Tests prompts designed to extract:

  * System instructions
  * Hidden context
  * Few-shot examples
  * Task configuration
* Tests both v1 and v2.
* Records raw model responses and leakage results.

### scripts/test_task_3.py

* Tests the input guardrail implementation.
* Tests legitimate IRIS inputs.
* Tests adversarial inputs.
* Tests invalid feature schemas.
* Verifies that malicious or malformed inputs are blocked before reaching the model.

### scripts/test_task_4.py

* Tests the output guardrail implementation.
* Tests valid species responses.
* Tests format violations.
* Tests context leakage.
* Tests unrelated model responses.
* Verifies that unsafe responses are replaced with the standardized fallback message.

### scripts/test_task_5.py

* Performs the complete guarded evaluation.
* Re-runs the Task 1 injection attacks.
* Re-runs the Task 2 leakage attacks.
* Tests both v1 and v2.
* Evaluates the Week 10 held-out IRIS dataset.
* Compares unguarded and guarded model accuracy.
* Calculates:

  * Injection block rate
  * Leakage block rate
  * False positive rate
  * Baseline accuracy
  * Guarded accuracy
  * Accuracy delta
* Saves detailed evaluation results as CSV files.

### data/

* Contains the Week 10 held-out IRIS evaluation dataset.
* Used to measure false positives and accuracy degradation caused by the guardrails.

### results/

Contains generated evaluation results from Task 5.

* `task5_adversarial_guarded.csv`

  * Detailed adversarial test results.
* `task5_baseline_results.csv`

  * Unguarded model evaluation results.
* `task5_guarded_results.csv`

  * Guarded model evaluation results.
* `task5_summary.csv`

  * Final guardrail effectiveness metrics.

### logs/

* Contains audit logs generated by the guardrails.
* Records blocked requests and filtered model responses.
* Includes timestamps, matched rules, and relevant input/output information.

### requirements.txt

Contains the Python dependencies required to execute the guardrail implementation and evaluation scripts.

### README.md

Provides an overview of the Week 11 implementation, guardrail architecture, evaluation methodology, and results.

* Prompt leakage attacks are tested against both model versions.

  `Iris classification unavailable.`

## Task 3 — Input Guardrails

The input guardrail uses two detection mechanisms.

### Rule-Based Detection

Detects known prompt injection patterns using keywords and regular expressions.

Examples include:

```text
ignore previous instructions
ignore all previous instructions
system prompt
hidden instructions
unrestricted assistant
general-purpose assistant
what instructions were you given
```

### Structural Validation

Validates that the request follows the expected IRIS schema:

```text
sepal_length
sepal_width
petal_length
petal_width
```

All feature values must be numeric.

Example blocked responses:

```text
{
    "blocked": true,
    "reason": "injection:instruction_override"
}
```

and:

```text
{
    "blocked": true,
    "reason": "schema:non_numeric:sepal_length"
}
```

## Task 4 — Output Guardrails

The output guardrail checks the model response after inference.

Valid species:

```text
Iris setosa
Iris versicolor
Iris virginica
```

The guardrail detects:

* Context leakage
* System prompt references
* Task configuration leakage
* Invalid species
* Unrelated responses
* Invalid output formats

Unsafe responses are replaced with:

```text
Iris classification unavailable.
```

Valid natural-language responses containing one valid species are normalized to the expected format.

For example:

```text
Based on the measurements provided,
the flower appears to be Iris setosa.
```

is converted to:

```text
Iris setosa
```

## Task 5 — Guardrail Effectiveness

The complete guarded pipeline is evaluated as:

```text
Adversarial / Legitimate Input
            │
            ▼
     Input Guardrail
            │
            ▼
       Vertex AI
            │
            ▼
     Output Guardrail
            │
            ▼
       Final Output
```

The following metrics are calculated:

### Injection Block Rate

```text
Injection Block Rate
=
Blocked Injection Attacks
-------------------------
Total Injection Attacks
× 100
```

### Leakage Block Rate

```text
Leakage Block Rate
=
Blocked Leakage Attacks
-----------------------
Total Leakage Attacks
× 100
```

### False Positive Rate

```text
False Positive Rate
=
Legitimate Inputs Blocked or Filtered
-------------------------------------
Total Legitimate Inputs
× 100
```

### Accuracy Delta

```text
Accuracy Delta
=
Guarded Accuracy − Baseline Accuracy
```

The ideal result is:

```text
Injection Block Rate  → 100%
Leakage Block Rate    → 100%
False Positive Rate   → 0%
Accuracy Delta        → 0 percentage points
```

* Prompt injection red-team testing

* Context leakage detection
